# FlowPlan

面向中文用户的本地优先智能规划工具。  
它把日程、任务、提醒、活动追踪、输入行为分析、智能排期、Outlook 同步、结构化导入导出和数据操作审计整合到同一个应用里，目标不是只“记录东西”，而是帮助用户真正看见时间去了哪里、计划是如何执行的、哪些改动发生过。

当前版本：`v1.3.3`  
当前构建号：`1.3.3+133`

## 产品定位

FlowPlan 的主线能力是五件事：

1. 用“日历本 / 任务本”管理所有日程与任务
2. 用智能排期把任务放进真实时间段
3. 用追踪能力记录实际执行情况
4. 用提醒和偏离检测把计划真正落地
5. 用 Outlook 与本地归档完成可控同步与恢复

这不是一个只靠云端服务的应用。FlowPlan 采用本地优先策略，核心数据默认保存在本地数据库中，用户可以导出、恢复、审计和检查自己的数据。

## 当前支持的平台

- Windows 桌面端
- Android 端

当前平台策略：

- Android 只面向 Android 16 及以上
- iOS / iPadOS 暂不在当前开发范围内
- Windows 与 Android 共用核心任务、日程、同步与提醒逻辑
- 键盘鼠标详细记录与热力图目前仅在 Windows 端提供

## 核心能力

### 1. 日历与任务体系

- 日程必须属于日历本
- 任务必须属于任务本
- 支持时间轴、本周、月视图三种主要日历视角
- 支持默认容器、颜色、可见性、归档与恢复
- 支持任务详情、日程详情、所属容器管理、字段编辑与删除

### 2. 智能排期

- 支持一键重排
- 支持多组工作时间
- 支持锁定任务、不拆分任务、可拆分任务
- 可拆分任务会生成持久化的“任务排程片段”
- 时间轴优先按排程片段渲染，而不是简单显示成一个大块
- 所有真正落库的排程改动都需要用户确认，不静默改数据

### 3. 提醒系统

- 日程支持提前提醒
- 任务支持开始提醒、截止提醒、截止风险提醒
- 偏离计划时可以触发提醒
- Windows 端具备应用内提醒、右下角通知与强提醒兜底
- Android 端已接入通知与精准闹钟相关能力，并支持重建提醒队列

### 4. 追踪系统

#### Windows

- 前台应用活动追踪
- 工作会话合并
- 原始活动日志查询
- 输入行为记录
- 键盘鼠标热力图
- 输入行为分析

#### Android

- 基于系统 `PACKAGE_USAGE_STATS` 的应用使用记录导入
- 仅在打开应用或手动刷新时读取系统记录
- 不做后台常驻追踪
- 追踪结果优先显示应用名而不是包名

### 5. 输入行为分析

Windows 端目前支持：

- 完整顺序化键盘 / 鼠标输入事件记录
- 输入事件与活动上下文关联
- 输入事件数据库存储
- 按天分割的输入日志归档
- 高频按键统计
- 应用内输入强度分析
- 时间段分布分析
- 键盘热力图
- 鼠标热力图

### 6. Outlook 同步

当前同步语义已经明确为三态：

- 只读
- 双向同步
- 暂停同步

同步安全边界：

- 普通 Outlook 日历默认只读
- 双向同步只允许写入 FlowPlan 托管的专属容器
- 任务通过专属镜像容器做跨设备同步
- 所有高风险同步动作都应有日志可查

### 7. 导入导出与恢复

- 支持 `.ics` 导入导出
- 支持 FlowPlan 结构化容器归档导入导出
- 支持数据库导出
- 支持数据库恢复准备、应用恢复、取消待恢复
- 用户可以直接拿到数据库文件进行第三方检查

### 8. 数据操作审计

除高频追踪采样外，核心数据操作已逐步纳入审计范围：

- 任务创建、修改、删除、完成
- 日程创建、修改、删除
- 日历本 / 任务本关键操作
- 结构化导入导出
- 数据库恢复相关操作
- Outlook 同步相关高风险写入
- 排程应用与排程片段替换

应用内也已提供“数据操作审计”查询入口。

## 主要数据存储

当前项目以本地数据库为核心存储层，配合部分按天归档的日志文件：

- SQLite：主业务数据、追踪数据、输入事件、审计日志
- JSONL：按天分割的活动日志与输入日志归档

建议理解为：

- 数据库是主事实来源
- 日志文件是长期追踪与人工检查的辅助归档

## 目录概览

```text
lib/
  core/               应用级基础设施、数据库、路由、版本信息
  features/
    calendar/         日历本、日程、时间轴、本周、月视图
    task/             任务本、任务详情、未排程任务
    scheduler/        智能排期、排程片段、预案确认、执行反馈
    tracker/          活动追踪、工作会话、输入行为、热力图
    reminders/        运行时提醒、系统提醒、恢复机制
    sync/             Outlook 同步、镜像容器、诊断与设置
    ical/             结构化归档与 iCalendar 导入导出
    audit/            数据操作审计页
    settings/         设置页、平台状态、数据管理
windows/
  runner/             Windows 壳、资源、图标、版本信息
android/
  app/                Android 清单、权限、原生配置
```

## 本地开发与手动验证

下面这些命令由你在本地终端手动运行即可。我这里不执行这些命令，只给你用于 release 验证。

### 1. 查看 Flutter 运行环境

```powershell
flutter doctor -v
flutter devices
```

### 2. Windows 构建

```powershell
flutter build windows --release
```

如果你还想本地直接启动桌面版做冒烟验证：

```powershell
flutter run -d windows
```

### 3. Android 构建

生成可安装 APK：

```powershell
flutter build apk --release
```

生成应用商店使用的 AAB：

```powershell
flutter build appbundle --release
```

如果已经连上安卓设备，先确认设备：

```powershell
adb devices
flutter devices
```

然后运行到真机：

```powershell
flutter run -d <你的安卓设备ID>
```

### 4. 建议你手动完成的最小验证清单

#### Windows

- 启动应用
- 进入时间轴、本周、月视图、追踪、设置，确认主导航高亮正常
- 创建、编辑、删除日程
- 创建、编辑、删除任务
- 任务本 / 日历本创建、编辑、归档、恢复、删除
- 一键重排与确认应用
- 追踪页手动刷新
- 追踪详细数据页、输入分析页、热力图页能正常打开
- 导出数据库、打开数据目录、导入导出归档
- Outlook 设置页能正常打开，三态同步文案正确

#### Android

- 启动应用
- 手机与平板布局检查
- Usage Access 权限引导
- 追踪页手动刷新
- 任务 / 日程查看与编辑
- 提醒状态展示
- Outlook 设置页移动端布局

#### Outlook 安全验证

- 只读模式下，FlowPlan 不写入 Outlook
- 暂停同步下，不拉取也不推送
- 双向同步下，只写 FlowPlan 托管容器
- 冲突候选与诊断报告可见

## 权限与数据说明

当前项目涉及以下敏感能力，正式发布前建议你继续人工复核：

- Windows 管理员权限
- Windows 键盘鼠标输入记录
- Android `PACKAGE_USAGE_STATS`
- Android 通知权限
- Android 精准闹钟
- Outlook OAuth 授权

这些能力的用途应限定为：

- 追踪用户自己的活动记录
- 生成提醒与排期反馈
- 进行可控的 Outlook 同步
- 帮助用户导出、审计和恢复自己的数据

## 已知限制

- Android 不做后台常驻追踪，只在打开应用或手动刷新时导入 Usage Stats
- Android 端当前不记录键盘鼠标输入行为
- `.ics` 合并导出不保留日历本边界，跨容器完整结构以 FlowPlan 自有归档格式承接
- Outlook 双向同步仍采用较保守的安全策略，优先防止误写入
- 偏离识别目前以规则型逻辑为主，还不是语义模型
- 项目是否可正式 release，仍取决于你本地的真实构建与冒烟验证结果
