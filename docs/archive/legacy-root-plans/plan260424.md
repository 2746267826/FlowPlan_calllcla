## 3. 当前新增待修改项

### 3.1 Outlook 日历本的阻挡排程默认项

当前已经做到：Outlook 来源日历本本身不能像普通本地日历本那样随意修改，以避免破坏远端同步数据。

但需要补充：

- Outlook 来源日历本应允许修改“是否统一启用阻挡自动排程”的本地默认策略。
- 该设置只影响 FlowPlan 本地排程器如何看待该 Outlook 日历本下的日程。
- 该设置不得写回 Outlook。
- 该设置不得修改 Outlook 日历本名称、颜色、远端 ID 或远端日程内容。
- UI 上应明确表达这是“本地排程策略”，不是 Outlook 远端修改。

建议实现方向：

- 在日历本默认规则中保留 `defaultIsBlock` 一类本地设置。
- 对 Outlook 来源日历本开放此设置项。
- 禁止修改 Outlook 来源日历本的远端同步核心字段。
- 排程器读取日程阻挡状态时，优先看日程自身 `isBlock`，若未来加入“继承”语义，则回退到日历本默认阻挡策略。

## 8. P3：日历本 / 任务本 / 条目模型补强

目标：把容器模型做清楚，防止任务和日程逻辑继续散落。

待做：

- 所有日程必须属于日历本，所有任务必须属于任务本。
- 日历本支持默认阻挡自动排程。
- Outlook 来源日历本可修改“本地默认阻挡自动排程”，但不能修改远端核心信息。
- 任务本支持默认自动排程、默认提醒、默认可拆分、默认锁定策略。
- 新建任务 / 日程继承容器默认值。
- 条目级设置能覆盖容器默认值。
- 删除 / 归档容器前必须处理其下属条目。
- 同步容器删除必须区分本地删除、解除绑定、远端删除，不得混淆。

## 9. P4：排程算法模型整理

目标：让自动排程从“能排”进化为“可解释、可调整、可确认”。

待做：

- 明确排程输入模型：任务、日程、工作时间、锁定段、阻挡段、追踪证据。
- 明确排程输出模型：任务排程片段、未排原因、冲突原因、建议变更。
- 继续强化 `task_schedule_segments`，让它成为任务实际排程的核心表现。
- 支持多组工作时间，处理中午休息、晚间学习、周末差异。
- 支持优先级、截止时间、预计时长、可拆分、锁定、阻挡日程综合排序。
- 所有自动改动必须先生成预案，用户确认后再写入。
- 排程预案和最终应用都必须写入审计日志。

## 10. P5：任务提醒模型整理

目标：提醒不只是一个字段，而是一个可靠的时间触达系统。

待做：

- 日程提醒以确定时间提醒为主。
- Windows 使用托盘 / 系统通知，不再弹软件置顶窗口。
- Android 使用通知和精准闹钟能力。
- 任务提醒分为计划开始提醒、截止提醒、截止风险提醒、长期未推进提醒。
- 任务提醒应结合预计时长、截止时间、优先级、当前排程、追踪证据。
- 用户完成任务、重排任务、改动提醒设置后，应自动重建提醒计划。
- 提醒计划应能被查询、诊断和手动重建。

## 11. P6：追踪融合模型整理

目标：追踪不只是展示数据，而是服务任务判断和排程调整。

待做：

- 主追踪页继续做摘要工作台。
- 工作会话、原始日志、键鼠输入、应用使用、热力图全部保持二级页面。
- 输入行为分析与工作会话继续双向联动。
- 追踪证据能绑定到任务。
- 追踪发现用户没有执行计划任务时，只提示是否重排，不静默改。
- Android 端追踪显示应用名，隐藏无意义包名。
- 优化追踪数据查询性能：所有涉及日期、应用、分类、任务关联、输入类型、时间段筛选的查询，应优先在数据库层下推筛选和聚合，避免把大量原始记录拉回 Dart 后再过滤。
- 为追踪相关大表补充必要索引、复合索引和轻量聚合表，重点覆盖 `activity_records`、`raw_activity_logs`、`tracked_input_events`、工作会话与热力图/输入分析使用的时间范围查询。
- 对追踪二级页面采用分页、游标加载、区间懒加载和结果缓存；默认只加载当前可见范围，避免切换筛选条件时长时间空白加载。
- 对高频统计项引入按日/按小时预聚合或增量刷新机制，减少每次进入页面都全量扫描历史数据。
- 未来预留电脑日志同步到手机查看，但当前不做服务器。

## 12. P7：Outlook 同步体验与安全边界优化

目标：Outlook 成为可靠同步底座，但不能破坏用户已有数据。

待做：

- 继续使用 `consumers + PKCE + nativeclient` 登录方案。
- 普通 Outlook 日历默认只读。
- FlowPlan 托管任务镜像容器才允许受控写回。
- Outlook 日历本可设置本地排程策略，包括默认阻挡自动排程。
- 同步冲突必须人工确认。
- 远端写回必须有审计日志。
- 增加单条 Outlook 日程原始字段诊断能力，方便排查标题、地点、备注、时区问题。
- 完善 HTML 正文解析和特殊实体解析。
- 继续保持“完全重置本地 Outlook 日历本”能力，不影响 Outlook 服务器数据。

## 13. P8：数据管理、审计与备份体验完善

目标：用户可以拿到、看懂、修改、备份自己的数据。

待做：

- “全部任务与日程管理”继续增强。
- 支持按日历本 / 任务本筛选。
- 支持批量移动任务本 / 日历本。
- 支持批量修改状态、提醒、优先级、阻挡排程。
- 支持导出所选任务 / 日程。
- 支持展示最近操作审计记录。
- 数据库路径、导出路径、日志路径继续保持可见。
- 数据库结构需要继续为大数据量场景优化：增加查询计划友好的索引、聚合表、分页 API、导出友好视图和清理/归档策略。
- 所有“追踪”相关筛选查询需要有性能基线：默认当天、最近 7 天、最近 30 天、大量键鼠输入数据、跨应用筛选均应避免长时间加载。
- 所有高风险批量操作必须确认并写审计。
