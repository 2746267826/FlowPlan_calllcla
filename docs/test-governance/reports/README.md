# Test Governance Reports

Generated reports live under `docs/test-governance/reports/generated` and are ignored by Git. Commit stable governance files, matrices, and acceptance templates.

Reports must distinguish `verified`, `partial`, `planned`, `pending-user`, and `blocked-environment` evidence. Manual acceptance reports must include the exercised buttons or controls, status states, error paths, side effects, exact steps, and dated passing evidence. Flutter/Dart commands are now executable by Codex after the 2026-06-08 user authorization, and Windows Flutter integration evidence passes when run per file. Real devices, credentials, external services, notification permissions, long-running checks, and Chrome or Edge unsupported Flutter integration launches remain manual or environment-blocked acceptance.

Root reports should include the governance matrix validation result. The root gate validates feature rows, manual acceptance rows, coverage exclusions, cross-referenced manual IDs, and focused/skipped test markers before it runs boundary, server, web, or Flutter gates.
