# 第四部分：H 文件上下文与本地文件管理

## 1. 目标

H 模块的目标不是“在任务里放几个文件夹链接”，而是建立一个像网盘一样的 FlowPlan 文件中心。

用户应该能在 FlowPlan 里看到统一的资料空间：

```text
FlowPlan 文件中心
  本地资料库
    课程资料
    项目资料
    作业资料
    论文资料
  任务相关文件
  日程相关文件
  最近使用
  推荐资料
  历史版本
  云端文件入口
```

文件内容可以仍然存放在本地真实路径、服务端对象存储、OneDrive 或未来其他后端中，但 FlowPlan 要提供统一的“网盘式体验”：

1. 能浏览文件树，而不是只显示文件夹快捷方式。
2. 能搜索文件名、路径、标签、任务、日程、项目。
3. 能看到最近使用和推荐资料。
4. 能在任务/日程详情里看到相关文件。
5. 能预览常见文件。
6. 能调用系统默认程序打开。
7. 能检测路径失效。
8. 能记录文件操作审计。
9. 能和历史版本、云文件、传输系统衔接。
10. 能尽量复用成熟库和外部软件，减少原生实现。

一句话目标：

```text
不是“任务里挂一个路径”，而是“FlowPlan 内部有一个统一资料库视图，任务和日程只是从这个资料库里关联文件”。
```

---

## 2. 设计原则

### 2.1 文件仍由真实后端保存

FlowPlan 不应该一开始把所有文件都复制进自己的数据库。

推荐：

```text
文件内容：仍在本地文件系统 / 服务端对象存储 / OneDrive / 未来 WebDAV
文件元数据：进入 FlowPlan 数据库
文件索引：进入 FlowPlan 文件树
文件操作：通过 FlowPlan 统一入口触发并审计
文件历史：交给 Kopia 或服务端版本系统
```

### 2.2 建立“资料库 Root”概念

用户不是给某个任务临时塞一个文件夹链接，而是先把一个真实文件夹登记为资料库 Root。

例如：

```text
D:/FlowPlan资料库
D:/课程资料
D:/项目资料
C:/Users/xxx/OneDrive/学校
Android/FlowPlanDocuments
```

每个 Root 进入 FlowPlan 后，系统会扫描并建立文件树索引。

### 2.3 任务/日程绑定的是文件中心里的节点

任务不直接绑定裸路径，而是绑定 `file_node_id`。

```text
任务 “数据库课程作业”
  -> 绑定文件节点：课程资料/数据库/作业3
  -> 推荐文件节点：课程资料/数据库/课件/SQL.pdf
  -> 最近相关文件：homework3.sql、report.md
```

这样以后路径移动、云端同步、历史版本、OneDrive 映射都能继续维护关系。

### 2.4 本地路径是实现细节，不是用户体验中心

用户看到的是：

```text
课程资料 / 数据库 / 作业3 / report.md
```

而不是裸露的系统绝对路径。真实路径可以放在详情或调试信息里。

## 3. 可复用库和外部软件建议

目标：尽量不要自己造文件选择器、文件预览器、文件监听器、全文提取器、备份系统。

### 3.1 Flutter 客户端推荐库

| 能力 | 推荐方案 | 用途 |
|---|---|---|
| 选择文件/目录 | `file_selector` 或 `file_picker` | 用系统原生文件选择器选资料库 Root |
| 目录变更监听 | `watcher` | 监听本地文件新增、删除、修改 |
| 拖拽导入 | `desktop_drop` | Windows/macOS/Linux 桌面拖文件到 FlowPlan |
| 调系统默认程序打开 | `open_filex` 或桌面端 `url_launcher file:` | 双击文件时交给系统打开 |
| PDF 预览 | `pdfrx` | 内置 PDF 查看，不自己实现 PDF 渲染 |
| 缩略图 | 首版先用文件类型图标，后续评估 `thumbnailer` | 降低首版复杂度 |
| 图片预览 | Flutter 原生 Image + 缓存 | 图片直接预览 |
| 文本/Markdown 预览 | Flutter 文本组件 / Markdown 渲染库 | 轻量预览和编辑 |

推荐策略：

- 首版不要实现复杂 Office 内置预览。
- Word、PPT、Excel 优先调用系统默认程序打开。
- PDF 可以内置预览，也可以先调用系统打开。
- 文本、Markdown、代码文件可以内置预览和轻量编辑。
- 大文件不要直接读取到内存。

### 3.2 服务端/后台推荐工具

| 能力 | 推荐方案 | 用途 |
|---|---|---|
| 文件全文和元数据提取 | Apache Tika | 解析 PDF、Office、文本等，用于搜索索引 |
| 对象存储 | MinIO / S3 兼容存储 | 服务端文件存储后端 |
| 历史版本 | Kopia | 快照、版本、恢复、挂载浏览 |
| 云盘统一访问 | rclone | 后续统一接 OneDrive、WebDAV、S3 等后端 |
| P2P 文件夹同步参考 | Syncthing | 可作为设备间同步和状态 API 的参考，不建议一开始深度嵌入 |
| 服务端文件扫描 | fast-glob / Node fs | 扫描服务端托管目录 |
| 服务端文件监听 | chokidar | 监听服务端本机目录变化 |

### 3.3 不建议首版做的事

- 不要自己实现 Office 预览器。
- 不要自己实现 PDF 渲染器。
- 不要自己实现完整备份系统。
- 不要一开始把 rclone mount、Syncthing、Kopia 全部深度耦合进主流程。
- 不要把所有文件内容塞进 PostgreSQL。
- 不要让 Flutter 主线程扫描巨型目录。

### 3.4 推荐复用边界

```text
Flutter：负责文件中心 UI、选择 Root、预览、打开、基础监听
服务端：负责文件元数据、云端索引、对象存储、审计、全文搜索
Kopia：负责历史版本快照
Apache Tika：负责全文/元数据提取
rclone：作为未来云盘后端适配层候选
系统文件管理器：负责复杂文件操作和外部打开
```

## 4. 用户流程

### 4.1 首次建立资料库

```text
用户打开 FlowPlan 文件中心
  -> 点击“添加资料库”
  -> 选择“本地文件夹”
  -> 系统调用原生目录选择器
  -> 用户选择 D:/课程资料
  -> FlowPlan 创建 file_roots 记录
  -> 后台扫描该目录
  -> 生成 file_nodes 文件树
  -> 文件中心显示完整目录结构
```

用户看到：

```text
文件中心
  课程资料
    高等数学
    数据库
    软件工程
    英语
```

### 4.2 像网盘一样浏览文件

```text
用户打开文件中心
  -> 左侧是资料库和分类
  -> 中间是文件树/文件列表
  -> 右侧是预览和详情
```

典型布局：

```text
左侧：资料库 / 最近 / 任务相关 / 日程相关 / 收藏 / 历史版本
中间：文件列表，支持排序、搜索、筛选
右侧：预览、元数据、关联任务、历史版本、操作记录
```

### 4.3 任务绑定资料

```text
用户打开任务详情
  -> 看到“相关资料”区域
  -> 系统自动推荐文件夹和文件
  -> 用户点击“绑定”
  -> 任务记录关联 file_node_id
```

推荐理由示例：

```text
推荐：课程资料/数据库/作业3
原因：
- 文件夹名包含“数据库”
- 最近在 VS Code 中打开过该路径
- 任务标题包含“数据库课程作业”
- 该任务明天截止
```

### 4.4 日程绑定资料

```text
用户打开课程日程
  -> 看到“课程资料”区域
  -> 系统推荐对应课程文件夹
  -> 用户确认绑定
  -> 后续该课程日程自动显示课件、作业、最近文件
```

### 4.5 打开文件

```text
用户双击 report.md
  -> 如果是文本/Markdown，可在 FlowPlan 内预览
  -> 如果用户选择“系统打开”，调用默认编辑器
  -> 记录最近使用
  -> 记录文件与当前任务/日程上下文
```

### 4.6 文件路径失效

```text
用户移动了 D:/课程资料 到 E:/课程资料
  -> FlowPlan 下次扫描发现 root 不存在
  -> 文件中心显示“资料库路径失效”
  -> 用户点击“重新定位”
  -> 选择新路径
  -> 系统根据相对路径、文件名、大小、mtime、hash 重新匹配
  -> 恢复 file_node_id 关联
```

### 4.7 文件拖拽导入

```text
用户把一个文件拖到 FlowPlan 任务详情
  -> 系统识别当前任务上下文
  -> 提示：复制到任务资料文件夹 / 仅建立关联 / 移动到资料库
  -> 用户确认
  -> 执行文件操作
  -> 写入审计
```

默认建议：

- “仅建立关联”风险最低。
- “复制到资料库”适合收集资料。
- “移动到资料库”高风险，必须确认。

## 7. 扫描与索引

### 7.1 首次扫描

```text
用户添加 Root
  -> 后台扫描目录树
  -> 分批写入 file_nodes
  -> UI 显示扫描进度
  -> 大目录不阻塞主界面
```

扫描策略：

- 先扫目录结构和基础元数据。
- 文件 hash 延迟计算。
- 缩略图延迟生成。
- 全文索引延迟生成。
- 大文件跳过全文读取。

### 7.2 增量扫描

来源：

- 文件系统 watcher。
- 手动刷新。
- App 启动后快速对比 mtime。
- 后台低频重扫。

增量事件：

```text
created
modified
renamed
moved
deleted
missing
restored
```

### 7.3 移动/重命名识别

不要简单把“旧文件删除 + 新文件创建”当成完全无关。

匹配信号：

```text
文件名相同
大小相同
mtime 接近
hash 相同
相对路径相似
父目录移动
```

如果能匹配，应更新 `relative_path`，保留 `file_node_id`。

## 8. 文件预览策略

### 8.1 首版支持级别

| 文件类型 | 首版策略 |
|---|---|
| txt / md / json / yaml / csv / code | 内置文本预览，部分可编辑 |
| 图片 | 内置图片预览 |
| PDF | 使用成熟 PDF 组件预览 |
| Word / PPT / Excel | 调系统默认程序打开 |
| 视频 / 音频 | 首版调系统默认程序，后续再考虑内置播放 |
| 大文件 | 不自动预览，只显示信息和打开按钮 |
| 未知类型 | 显示文件信息，调用系统打开 |

### 8.2 文本编辑保护

文本文件在 FlowPlan 内编辑时：

```text
打开文件
  -> 读取内容
  -> 用户编辑
  -> 保存前创建备份或版本记录
  -> 写入文件
  -> 更新 file_nodes mtime/hash
  -> 写入 file_operation_logs
```

首版可以只支持小文本文件，例如小于 2MB。

### 8.3 Office 文件策略

不要自己解析和编辑 Office。

推荐：

- 用 Apache Tika 做服务端全文提取和搜索。
- 用系统默认程序打开 Office 文件。
- 只展示基础元数据和关联关系。

## 13. 同步、离线与冲突

### 13.1 哪些数据同步

| 数据 | 同步策略 |
|---|---|
| file_roots | 同步元数据，但本地路径按设备区分 |
| file_nodes | 同步摘要和相对路径，hash 可选 |
| file_links | 必须同步 |
| file_recent_items | 可同步摘要，也可按设备保留 |
| file_recommendations | 同步 |
| file_operation_logs | 同步审计摘要 |
| 文件内容 | 不属于 H，交给 I/J 模块 |

### 13.2 本地路径的特殊处理

同一个文件节点在不同设备上可能有不同本地路径。

需要单独建映射：

```text
file_node_device_locations
  node_id
  device_id
  local_path
  availability       available / missing / remote_only / downloading
  last_seen_at
```

这样：

- Windows 可能有 `D:/课程资料/数据库/report.md`。
- Android 可能是 `/storage/emulated/0/FlowPlan/课程资料/数据库/report.md`。
- OneDrive 可能只有云端 driveItemId。

### 13.3 冲突场景

| 场景 | 处理 |
|---|---|
| 两端同时重命名同一文件节点 | 冲突候选 |
| 一端删除，一端绑定到任务 | 高风险冲突，人工确认 |
| 本地路径失效但云端仍存在 | 标记本地 missing，不删除节点 |
| 用户移动文件夹 Root | 重新定位，不创建全新节点树 |
| 推荐被一端接受、一端拒绝 | 用户操作冲突，人工或最近操作优先 |

## 14. 异常与边界情况

必须考虑：

1. 路径不存在。
2. 权限不足。
3. 文件被占用。
4. 文件名乱码或编码异常。
5. 超大目录扫描太慢。
6. 超大文件误预览导致卡顿。
7. 重命名和移动被识别成删除+新增。
8. Android 作用域存储限制。
9. Windows 路径过长。
10. OneDrive 占位文件未本地化。
11. 文件正在被外部程序修改。
12. 用户在 FlowPlan 外删除文件。
13. 资料库 Root 被移动。
14. 文件 hash 计算太慢。

处理原则：

- 不崩溃。
- 不静默删除关联。
- 不阻塞主界面。
- 高风险操作必须确认。
- 所有失败可重试或重新定位。

## 15. 安全与隐私

文件模块涉及大量私人资料，必须保守。

规则：

- 默认只索引文件名、路径、大小、修改时间。
- 全文索引需要单独开关。
- 敏感目录可加入忽略列表。
- 聊天、证件、密码、财务、医疗等目录默认不推荐纳入。
- AI 默认只能看到文件名、路径摘要、任务关联，不读取完整文件内容。
- 读取文件正文给 AI 必须用户明确确认。
- 删除、移动、覆盖、恢复旧版本必须确认。
- 文件操作写审计。

## 17. 验收标准

### `[B] 骨架完成`

满足：

- 有文件 Root 表。
- 有文件节点表。
- 有任务/日程文件关联表。
- 有最近使用和推荐基础。
- 有文件中心或文件上下文页面入口。

### `[M] MVP 可用`

必须实测：

- 用户能添加一个真实本地资料库 Root。
- FlowPlan 能扫描并显示文件树。
- 用户能像网盘一样进入子文件夹。
- 用户能搜索文件。
- 用户能在任务详情绑定文件夹或文件。
- 用户能打开和预览常见文件。
- 路径失效时能提示重新定位。
- 文件操作能写入日志。

### `[V] 已验证可用`

必须实测：

- 大目录扫描不会卡死。
- 文件新增、删除、修改能增量更新。
- 文件移动后能尽量保持原 file_node_id。
- 任务/日程推荐有可解释理由。
- Android 和 Windows 都能使用对应文件中心能力。
- 文件元数据能同步到服务端。
- 本地路径按设备正确区分。

### `[S] 稳定可用`

必须具备：

- 扫描性能测试。
- 大文件预览保护。
- 权限失败处理。
- 路径失效恢复演练。
- 文件操作审计完整。
- 文件索引可重建。
- 长期使用不会产生大量重复节点。
