# FlowPlan 完整优先级开发总计划（2026-04-26）

## 0. 文档定位

本文是当前 FlowPlan 的权威开发路线图。它整合了根目录历史计划、P0 架构文档、近期新增产品要求和已经落地的 P0 代码底座。

后续讨论“P0、P1、P2”时，以本文的阶段定义为准。

## 1. 产品目标

FlowPlan 的长期目标不是单纯的日历或待办工具，而是一个以时间为主轴的个人执行系统：

```text
计划日程 + 任务管理 + 活动追踪 + 实际记录 + 文件上下文
+ 服务端同步 + Web 管理 + AI 聊天 + 外部聊天入口
+ 位置/天气/蓝牙等现实上下文
```

它最终应做到：

- 计划知道“应该做什么”。
- 追踪知道“实际做了什么”。
- 实际记录沉淀“最终发生的事实”。
- 文件系统知道“做这件事需要哪些材料”。
- 服务端保存完整数据并提供跨端同步、统计聚合、Web 管理和备份。
- AI 能理解上下文，但只能生成草稿、预案、回执，不能绕过人工确认。
- 日报、周报、月报和自动日记能定期生成，并可推送到 Telegram 等聊天渠道。

## 2. 不变原则

1. 服务端完整存储  
   所有核心信息最终都应同步到服务端。服务端是完整事实库，不是简单备份。

2. 本地可用  
   客户端继续保留本地数据库、本地缓存和离线写入能力。网络差时允许继续使用，并明确标识未同步数据。

3. 服务端统计聚合  
   热力图、趋势图、输入统计、区间分析、日报统计等大量数据计算由服务端查表聚合，客户端只拿最终统计结果和少量明细。

4. 所有自动操作必须人工确认  
   自动排程、AI 修改、冲突处理、文件移动、批量操作、阻挡日程生成实际记录等，都必须先生成预案或回执，经用户确认后执行。

5. 全部可追溯  
   关键操作写审计日志。高频原始追踪数据不进入普通审计，但其导入、清理、同步、导出、权限变更必须审计。

6. 隐私分层  
   原始键盘输入、聊天内容、位置轨迹等敏感数据即使同步到自有服务端，也不得直接进入第三方 LLM API。外部 AI 只能接收脱敏摘要。

7. 模块独立，信息综合  
   各功能模块独立开发，但统一汇入 `UserContext`，供排程、日报、AI 和文件推荐使用。

8. 保留 Flutter 主客户端  
   Windows/Android 主客户端继续使用 Flutter。当前目标是把 Flutter 从本地单体重构为客户端外壳、本地缓存、原生采集、人工确认界面。

9. Web 管理面板独立建设  
   Web 管理面板优先使用 Next.js 或 Vite React，不使用 Flutter Web 承担复杂后台。

10. 禁止 Codex 运行 `flutter` / `dart` 指令  
    该约束见 `docs/development_constraints_260426.md`。如需格式化、分析、测试，由用户手动执行。

## 3. 总体架构

```text
Flutter 客户端
  本地缓存、离线写入、日常交互、原生采集、文件打开、人工确认

FlowPlan Server
  完整事实库、跨端同步、统计聚合、文件存储、报告、AI 后台任务、审计

Web 管理面板
  数据管理、同步状态、设备状态、冲突处理、审计、统计图、远程配置

外部入口
  Telegram、Webhook、系统分享、未来 QQ/微信辅助入口
```

## P1：数据同步、本地缓存、同步状态与冲突模型

### 目标

让核心信息最终同步到服务端，同时本机保留可用副本。网络差时可继续使用，并清楚展示未同步状态。

- 日历本、任务本。
- 日程、任务。
- 排程片段。
- 操作审计。
- 跨端必要设置。

### 第二批同步对象

- 实际记录。
- 活动片段。
- 活动理解结果。
- 任务实际投入。
- 文件元数据。
- 文件绑定关系。
- AI 对话摘要和操作预案。

### 第三批同步对象

- 原始活动日志。
- 键鼠输入事件。
- 位置采样。
- 更完整的 AI 会话。

第三批可以后台分批、压缩、延迟上传，不要求实时阻塞。

### 必须完成

- 服务端 PostgreSQL 数据模型。
- 设备注册和设备心跳。
- 同步游标。
- 离线变更队列。

### 验收

- 断网时能创建/修改任务和日程。

## P4：实际记录系统与阻挡日程自动候选

### 目标

明确区分计划、证据和事实。日程/任务是计划，追踪是证据，实际记录是最终事实。

### 数据模型

已新增：

```text
actual_activity_logs
  id
  title
  start_at
  end_at
  source_type
  source_id
  confidence
  status
  note
  created_at
  confirmed_at
```

### 阻挡日程候选

当阻挡日程满足以下条件时生成实际记录候选：

- `isBlock = true`
- 时间已结束。
- 状态不是取消。
- 对应时间段没有其他已确认实际记录。
- 没有明显冲突的追踪证据。

注意：只生成候选，不静默写入最终实际记录；确认、拒绝、合并都写入审计并进入同步对象。

### 验收

- [x] 课表、会议、考试等可生成实际记录候选。
- [x] 用户确认后才成为正式实际记录。
- [x] 结果已作为日报、周报和排程反馈的数据源，具体展示在 P7/P6 接入。

## P13：位置、天气、蓝牙与现实上下文

### 目标

让系统获得更多现实上下文，提高日报、实际记录和排程准确性。

- 用于出行缓冲、户外任务建议、日报解释。
- 只作为软约束，不静默改计划。

### 蓝牙 / STM32

- STM32 只作为未来实验能力。
- 可记录与手机蓝牙长连接状态。
- 可用于判断设备是否随身、是否遗落。
- 不作为近期主线。

### 验收

- 上下文进入报告和建议，但不静默写关键事实。

## P14：生态扩展与插件体系

### 目标

- 本地自动化入口。
- 插件式文件后端。

### 验收

- 插件或 Provider 的权限边界清晰。

## P15：长期智能、隐私治理与生态扩展

### 目标

在基础数据可信、同步稳定、报告和 AI 工具调用安全后，再发展长期智能和生态入口。

### 长期智能

- 每日/每周趋势总结。
- 任务耗时预测。
- 文件夹推荐学习。
- 个性化排程参数学习。
- 活动片段自动解释。
- 长期效率模式分析。

### 隐私治理

- 字段级加密。
- 同步范围开关。
- 数据导出与删除。
- 服务端访问审计。
- 第三方 LLM 脱敏过滤。
- 敏感数据保留周期。

### 不建议

- 直接训练端到端大模型。
- 让 LLM 直接生成最终数据库变更。
- 实时调用 LLM 分析每个窗口切换。
- 未建立隐私边界前同步全部敏感原始数据到第三方。

## 7. 一句话结论

FlowPlan 的正确路线是：

```text
先让数据可同步、可追溯、可离线
再让追踪查询变快
再让实际发生的事情可信
再让追踪进入排程
再让报告、文件、AI 和外部入口综合起来
最后发展长期智能和生态
```
