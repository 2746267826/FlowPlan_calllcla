## 1. 产品总目标

FlowPlan 不是单纯日历或待办工具，而是一个以时间和实际行为为核心的个人执行系统。

最终系统要综合：

- 计划日程、任务、任务本和排程片段
- 实际记录、阻挡日程候选、活动追踪和输入统计
- 文件、文件夹、项目资料、OneDrive 和服务端文件存储
- 服务端同步状态、冲突状态、审计日志和 Web 管理能力
- Outlook 任务读取、Outlook 日历镜像和外部日历同步状态
- AI 聊天、自然语言操作草案、Telegram 等外部聊天入口
- 位置、天气、蓝牙连接、未来可能的 STM32 等现实上下文
- 日报、周报、月报、自动日记和推送记录

最终效果：

- 系统知道“计划应该做什么”。
- 系统知道“实际发生了什么”。
- 系统能解释“计划和实际为什么偏离”。
- 系统能推荐“接下来应该做什么”。
- 系统能找到“做这件事需要哪些文件”。
- 系统能在多端之间同步完整数据。
- 系统能生成日报、周报、月报和日记。
- 系统能接入 AI，但所有写操作必须先回传草案并等待人工确认。

## 2. 不变原则

- [x] 服务端是完整事实库：所有核心信息最终都要同步到服务端。服务端不是简单备份，而是跨端同步、统计聚合、Web 管理、AI 后台任务和文件存储中心。
- [x] 本地继续保留数据：客户端必须保留本地数据库和缓存。网络差时仍可使用，并明确显示未同步、同步失败或冲突数据。
- [x] 大统计由服务端计算：热力图、趋势图、追踪筛选、输入统计、日报统计等由服务端查表聚合，客户端只拿统计结果和少量明细。
- [x] 自动操作必须人工确认：自动排程、阻挡日程生成实际记录、AI 修改任务、文件移动、冲突合并、Telegram 指令执行等，都必须先生成草案或回执。
- [x] 外部系统写入必须严格确认：未来写入 Outlook、OneDrive 或其他外部系统时，必须在提交前给出明确提示，说明写入对象、字段、时间范围和可能影响，并写入严格审计。
- [x] 所有关键操作可追溯：关键写操作、同步、冲突处理、AI 操作、文件操作、推送、权限变化都需要审计日志。
- [x] 模块独立，信息综合：日程、任务、追踪、文件、AI、日报、位置、天气等模块独立开发，但最终进入统一上下文。
- [x] 隐私分层：原始键鼠输入、位置轨迹、聊天内容等敏感数据默认谨慎同步和使用，发送给第三方 AI 时优先使用脱敏摘要。
