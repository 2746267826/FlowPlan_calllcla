# FlowPlan 真实完成度复核报告（2026-04-27）

依据：`docs/flow_plan_00_整体进程计划表_v_2.md`

复核范围：当前仓库 `server/`、`client_flutter/`、`web_admin/`、`docs/`。

复核规则：

- 本次只做代码和文件结构复核，不开发新功能。
- 未运行 `flutter` 或 `dart` 指令。
- 未接入真实 Windows/Android 设备、OneDrive、Outlook、Telegram、AI API 或真实大文件传输。
- 没有真实端到端验证的模块，最高只标到 `[B]`。
- 同步、文件、AI、外部系统写入、删除、历史版本恢复等高风险能力，即使已有表和接口，也不能直接视为稳定可用。

建议状态：`[B]`

主要文件和目录：

已经存在的能力：

- 仓库已拆为 `client_flutter`、`server`、`web_admin`、`docs`。
- 服务端使用 NestJS + PostgreSQL，已有 `npm run db:schema`、`npm run dev`、`npm run build`。
- Web 管理端使用 Vite React，已有静态服务器脚本和构建脚本。
- 服务端有 `/api/health`，当前 phase 已到 P11。
- 数据库统一由 `server/src/database/p1_schema.sql` 建表。

只是骨架、还不能算可用的能力：

- `health` 只返回固定服务状态，不检查数据库连接、对象存储、AI Provider、外部 API、队列积压。
- 没有统一一键启动 PostgreSQL、服务端、管理端、未来对象存储/Redis 的脚本。
- 没有 `.env.example`、生产部署说明、备份恢复脚本和恢复演练记录。
- 没有统一版本迁移编号，`p1_schema.sql` 实际承载了 P1-P11 多阶段 schema。

缺失的用户流程：

- 新机器从零启动完整开发环境。
- 更新 schema 后自动检查服务端、管理端、数据库是否一致。
- 本地数据备份、恢复、回滚。

缺失的异常处理：

- `DATABASE_URL` 缺失时会直接启动失败，缺友好的配置诊断。
- 没有数据库迁移失败后的回滚方案。
- 没有统一错误码和运行状态页。

缺失的 UI 或管理端入口：

- 管理端无“系统健康总览”独立页。
- 无数据库/对象存储/外部服务健康检查面板。
- 无备份、恢复、迁移状态入口。

推进到下一级 `[M]` 的最小任务：

- 新增一键启动和一键健康检查脚本。
- 增加 `.env.example` 和配置说明。
- `/api/health` 检查数据库 schema、数据库连接、关键表、AI 配置状态、文件存储状态。
- Web 管理端增加健康检查页。

用户手动验证步骤：

- 在新终端执行服务端 schema 和启动流程。
- 打开 Web 管理端并确认能连上服务端。
- 故意移除或写错 `DATABASE_URL`，确认错误提示可理解。
- 备份当前数据库，再恢复到新库，确认服务端可读。

缺失的 UI 或管理端入口：

- 管理端可看设备和同步状态，但没有设备撤销按钮。

推进到下一级 `[M]` 的最小任务：

- 引入真实 JWT 或会话校验。
- 增加设备禁用字段和撤销 API。
- Flutter 设置页显示当前用户、设备 ID、最后同步状态。
- 管理端增加设备撤销/重命名入口并写审计。

用户手动验证步骤：

- 心跳一次设备，确认最后在线时间变化。

## 2. 当前不应继续向后堆的原因

- 多数模块处于 `[B]`，也就是表、接口、页面入口和 Provider 已有，但真实用户闭环不足。
- `D 同步` 未验证前，后续所有云文件、AI、报告都可能建立在不可信数据上。
- `F 实际记录` 未验证前，日报和智能排程容易变成看起来完整但没有事实基础的总结。
- `I/J 文件` 目前服务端骨架和真实云盘/多路径传输差距较大，需要拆开验收。
- `K AI` 已有安全边界骨架，但没有真实模型返回、草案 diff、拒绝/确认完整验证，不能认为可用。

## 3. 推荐下一步

1. 先做 D 同步闭环实测，不新增功能。
2. 再做 F 一天真实活动数据复核。
3. 再做 K AI 草案闭环实测。
4. 再做 H/J 文件从本地到云文件的真实体验复核。
5. 最后做 L 日报是否引用真实证据的复核。

每个闭环通过后，再把对应模块从 `[B]` 推进到 `[M]`。只有真实设备、真实数据、真实外部服务端到端验证后，才允许进入 `[V]`。
